# Simple Agent

一个使用 Python 和 DeepSeek API 实现的最小 Agent 项目。该项目用来供我浅度学习 AI Agent 开发。

全程由 Codex 老师指导，所有代码（除了这个说明文档以及所有的笔记）纯手搓，边做边学确实学得快（笑）。

该项目的工作方式是让模型根据用户问题提出工具调用，Python 程序执行工具并回传结果，模型再决定继续调用工具还是生成最终回答。

## 功能

- 使用 `add` 计算两个数字的和。
- 使用 `read_note` 读取项目 `notes/` 目录中的 Markdown 笔记。
- 支持一轮多个工具调用请求，以及连续多轮工具调用请求。
- 默认最多请求模型 5 轮，无工具调用时输出回答并结束。
- 记录请求轮数、工具参数、执行结果和停止原因。
- 检查工具参数与文件路径，发生错误时提示原因并退出。

## 快速开始

以下命令以 Linux / Bash 为例。

已验证环境：Python 3.14.7，`openai` 2.49.0（2026-09-13 核对 `study` 环境）。

### 1. 进入项目目录并准备环境

在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
```

如果已经有准备好的 Python 环境，也可以直接激活该环境。

### 2. 安装依赖

```bash
python -m pip install openai
```

### 3. 配置 API 密钥

```bash
export DEEPSEEK_API_KEY="你的 Deepseek 密钥"
```

程序从环境变量读取密钥。不要把真实密钥写入源码或提交到仓库。

上述设置对当前终端会话及其启动的程序生效。

### 4. 启动程序

```bash
python main.py
```

默认演示会读取 `notes/basics.md`，然后让模型总结正文。

## 使用示例

当前通过修改 `main.py` 中的用户消息设置问题，程序不会在启动后等待终端输入。

找到 `messages` 中 `role` 为 `user` 的消息，修改其 `content`，保存后重新运行。

### 示例一：读取笔记

输入：

> 请调用 read_note 读取 basics.md，根据实际正文，用三点总结这份笔记的主要内容。

运行时应看到读取工具的调用日志、读取字符数，以及模型生成的总结。

一次实际运行的日志节选：

```text
[LOG] 第 [1] 次调用 SDK；待发送消息 [2] 条。
[LOG] 接收到模型的第 [1] 轮回复；本轮要调用 [1] 个工具。
……
      解析后的参数：[{'note_name': 'basics.md'}]；读取字符数：[3260]。
[LOG] 第 [2] 次调用 SDK；待发送消息 [4] 条。
[LOG] 接收到模型的第 [2] 轮回复；本轮要调用 [0] 个工具。
[LOG] 正常结束，模型的最终回答为：
……
```

字符数会随笔记内容变化，模型的回答措辞也可能不同。

### 示例二：连续计算

输入：

> 请先调用 add 计算 137＋289。收到工具返回结果后，再调用 add，将这个结果加 100。两步都必须使用工具，最后告诉我结果。

已验证的执行过程：

1. 第一轮调用 `add`，得到 426。
2. 第二轮调用 `add`，将 426 加 100，得到 526。
3. 第三轮模型输出最终回答，程序结束。

实际是否发生连续两轮工具调用，应以日志为准。

## 工作流程

1. 初始化客户端、工具列表和消息历史。
2. 将消息历史与工具说明发送给模型。
3. 如果模型提出工具调用，逐个校验参数并执行。
4. 将调用消息和工具结果追加到历史，进入下一轮。
5. 如果模型没有提出工具调用，输出回答并停止。
6. 如果请求次数耗尽，提示尚未获得最终答案，并以退出状态码 `1` 结束。

## 当前限制

- 用户问题需要在源码中修改。
- 消息历史只保存在本次运行的内存中。
- 工具按顺序执行，不进行并行调度。
- 参数错误或文件读取失败时退出，不自动重试。
- 读取工具只允许访问项目笔记目录中的 `.md` 文件。
- 笔记全文回传，暂未限制文件大小或消息历史长度。
- 模型请求抛出 `APIError` 时，程序显示错误原因并退出。已验证：使用无效密钥时，API 服务返回 401 认证错误，程序退出状态码为 `1`。
